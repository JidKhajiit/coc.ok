# Critter Trades

Веб-приложение для учёта коллекции и обменов картами в Clash of Critters.

## Возможности

- **Коллекция** — отмечать карты и количество (повторы доступны для обмена)
- **Нужные** — вишлист недостающих карт
- **Обмены** — история сделок; при сохранении количество в коллекции обновляется
- **Тренды** — какие карты чаще отдаёте и чаще получаете
- **Мультипользовательский режим** — у каждого пользователя своя коллекция в PostgreSQL

## Маршруты

| Путь | Описание |
|------|----------|
| `/` | Редирект на `/card-trades` |
| `/card-trades` | Ваше приложение (коллекция, обмены, тренды) |
| `/card-trades/collections` | Список публичных коллекций игроков |
| `/card-trades/collections/:slug` | Просмотр коллекции игрока (только чтение) |

Публикация своей коллекции — в **Настройки → Публичная коллекция**.

## Локальная разработка

1. Скопируйте переменные окружения:

```bash
cp .env.example .env
```

2. Запустите PostgreSQL:

```bash
docker compose -f docker-compose.dev.yml up -d
```

3. Установите зависимости и примените миграции:

```bash
npm install
npm run db:migrate
```

4. Запустите фронтенд и сервер:

```bash
npm run dev
```

- Фронтенд: http://localhost:5173 (проксирует `/api` на сервер)
- API/сервер: http://localhost:3000

При первом входе данные из `localStorage` автоматически переносятся на сервер, если аккаунт пустой.

## Production (Docker)

1. Создайте `.env` на основе `.env.example` и задайте:
   - надёжный `SESSION_SECRET` (минимум 32 символа);
   - `APP_URL` — публичный URL приложения (для Docker обычно `http://localhost:3000` или ваш домен);
   - при необходимости `SMTP_*` для отправки писем.

2. Запустите:

```bash
docker compose up -d --build
```

Приложение будет доступно на порту `3000` (или `APP_PORT` из `.env`). Compose подставляет значения из `.env` в контейнер `app` (включая `APP_URL` и SMTP).

PostgreSQL доступен только внутри Docker-сети — порт наружу не публикуется. `DATABASE_URL` для контейнера задаётся в `docker-compose.yml` и указывает на сервис `db`.

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `DATABASE_URL` | Строка подключения PostgreSQL |
| `SESSION_SECRET` | Секрет для сессий (мин. 32 символа) |
| `APP_URL` | Публичный URL фронтенда (ссылки в письмах) |
| `SMTP_HOST` | SMTP-сервер (если пусто — письма в лог сервера) |
| `SMTP_FROM` | Адрес отправителя |
| `ALLOW_REGISTRATION` | `true` / `false` — разрешить регистрацию |
| `TRUST_PROXY` | `true` если за reverse proxy |
| `COOKIE_SECURE` | `true` для HTTPS-only cookies |
| `PORT` | Порт сервера (по умолчанию 3000) |

## Регистрация и email

- Регистрация требует **email** — после создания аккаунта на почту уходит ссылка подтверждения.
- Вход возможен по **email или имени пользователя**; без подтверждённого email вход заблокирован.
- **«Забыли пароль?»** отправляет ссылку для сброса на указанный email.
- В dev без SMTP письма не отправляются — ссылки появляются в логе сервера (`[email:dev]`).
- Укажите `APP_URL` (URL фронтенда) и при необходимости `SMTP_*` в `.env`.

## Сборка

```bash
npm run build
npm start
```

## Безопасность

- API доступен только same-origin (сайт ↔ сервер)
- Сессии в httpOnly cookie, без публичных API-ключей
- Rate limit на `/api/auth/*`
- Данные пользователей изолированы по `user_id` из сессии
